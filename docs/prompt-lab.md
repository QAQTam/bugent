# 提示词实验台（prompt-lab）

改提示词最容易变成玄学：换两句措辞、看两条输出，就宣布"这样更好"。这个实验台
把它变成可复现的对照实验 —— 每个变体跑 N 次同一道题，统计推理里出现
`We need` / `Let me` 的比例，原始推理全量落盘，小样本用 Wilson 区间 + Fisher
精确检验。

## 怎么跑

```bash
# 1) 冻结当前仓库的提示词（改之前先存一份，否则改完就没法对照了）
bun run scripts/dump-tools.ts zh-baseline --system

# 2) 跑实验（默认 debug 题；--task study 是 study 里那道 Python 并发题）
bun run scripts/prompt-lab.ts --task study --trials 24 --concurrency 3

# 3) 只重算统计（不重跑模型）
bun run scripts/prompt-lab-analyze.ts .prompt-lab/runs/<...>/results.jsonl --baseline baseline-zh
```

环境变量：`PROMPT_LAB_BASE_URL`（默认本地网关 `http://127.0.0.1:8787/v1`）、
`PROMPT_LAB_MODEL`（默认 `deepseek-v4.1-flash`）、`PROMPT_LAB_EFFORT`（默认 `high`）。

快照放在 `.prompt-lab/snapshots/`（已 gitignore），所以"改前 / 改后"永远是同一把尺子。

## 结论

### 第一轮：工具 schema / system prompt / 角色（224 次运行）

主任务用 study 里那道 Python `TaskQueue` 并发题（够复杂，模型会真的规划）：

| 变体 | `We need` | 推理长度 |
|---|---:|---:|
| baseline：中文工具描述 + 旧 system.md | 11/52 = 21% | 6.9k chars |
| 只换工具 schema（短 + 纯英文） | 2/16 = 13% (p=0.72) | 6.6k |
| 只换 system prompt（纪律搬进来） | 7/16 = 44% (p=0.11) | 15.2k |
| 两者都换 | 15/44 = 34% (p=0.17) | 13.8k |
| 无工具 | 5/28 = 18% | 12.1k |
| 软措辞「陈述需求时用 We need to ...」 | 3/16 = 19% | 13.4k |
| **显式要求句式** | **27/36 = 75%** | 16.9k |

结论：

1. **任务实质是前提。** 另一组 144 次跑在"一眼能答完"的简单题上：所有变体
   **0/144**，连显式要求句式的也只有 1-2/16。
2. **唯一稳的杠杆是显式要求句式**（21% → 75%，p<0.001）。软措辞几乎无效 ——
   模型不会从"要求用某种句式"推断出"整段推理都用它"。
3. 工具 schema 的语言与长度对推理风格**没有可测出的影响**（13% vs 21%，
   p=0.72）。它的收益在省 24% token 与"纪律每轮都在"。

### 第二轮：提示词工程 + 强制思考风格（回答必须仍然简练）

在 system prompt 里补 `## Reasoning` / `## Answer` 两节：思考可以发散、必须避免
原地打转、**不许把推理复述进回答**；回答要短。然后在这之上加强制句式。

| 任务 | 变体 | `We need` | 推理字 | **回答字** |
|---|---|---:|---:|---:|
| study（Python 并发题） | baseline | 11/52 = 21% | 6932 | 2467 |
| study | PE（软措辞） | 6/20 = 30% | 11513 | 2982 |
| study | PE + 强制句式（软） | 9/20 = 45% | 10678 | 2535 |
| study | **PE + 强制句式（硬）** | **16/20 = 80%** | 9767 | 2510 |
| hard2（读写竞争） | baseline | 0/16 = 0% | 6712 | 2734 |
| hard2 | **PE + 强制句式（硬）** | **7/16 = 44% (p=0.007)** | 6018 | 1980 |
| brief（一句话简答） | baseline | 0/16 = 0% | 402 | 220 |
| brief | **PE + 强制句式（硬）** | **5/16 = 31% (p=0.043)** | 425 | 227 |

结论：

1. 强制句式写在哪、写多硬，差别很大：同一条要求写成"陈述需求时用 We need to"
   → 45%；写成 "Start every reasoning paragraph with 'We need'" → 80%。
2. **回答没有变长**：三个任务上 PE 版的回答字数与 baseline 持平或更短
   （hard2 甚至 2734 → 1980）。"思考发散、回答简练"这个分工是成立的。
3. 推理在难题上更长（study 6.9k → 9.8k 字），简单题上几乎不变（402 → 425 字）。

### 第三轮：把 Reasoning 段删到只剩 `We need` 会怎样

一个合理的直觉：模型看不到自己的推理摘要，所以"思考要发散""不要绕圈"这类
自我描述它没法照做，删掉只留 `We need` 校准应该更好。实测**不成立**。

hard2 任务（读写竞争题），每组 16-20 次，累计：

| Reasoning 段 | `We need` |
|---|---:|
| 完整版（5 条 bullet） | **30/76 = 39%** |
| 压成 3 行（同样内容，更少的字） | 3/20 = 15% |
| 只留 `We need` | 4/36 = 11% |
| 只留 `We need` + "长推理没问题" | 4/20 = 20% |
| 只留 `We need` + "不要叙述" | 2/20 = 10% |

- 完整版 vs 只留 `We need`：39% → 11%，Fisher p≈0.003
- 单独留哪一行都救不回来 —— 起作用的是**整块**，不是某一句
- 同一道题在 study 任务上删减无差异（75% → 70%），所以这是任务相关的：
  任务文本越短（hard2 只有一小段代码），Reasoning 段的相对权重越大

**怎么解释**：这些句子不是在要求模型"自省"，而是在**给推理定调**（priming）。
一整块"这是你的推理空间、要发散、按需求陈述、别复述代码"的文字，会把摘要的
语域从"叙述用户说了什么"推到"陈述需求"。砍成一行，语域就推不过去。

**结论：不要删。** 整段约 400 字符 / ~120 tok，在 hard2 上值 3 倍效果。

### 机制上的一个事实

我们能看到的"CoT"是上游的 **reasoning summary**（网关会补
`reasoning_summary: "auto"`），不是模型内部原始推理。这解释了为什么措辞类指令
效果弱、同一变体跨轮次波动大（`both` 先 58% 后 19%）。**能改的是摘要的风格，
不是推理本身。**

另外网关按账号池负载均衡，同一变体跨轮次的方差里有一部分可能来自上游路由到了
不同后端 —— 要更干净的数据得按账号分层统计。

## 还没覆盖的

- **多步 / 带工具循环的场景**：探索类任务会让模型直接发起工具调用，本实验台是
  单轮的，量不到（16 次跑出来全是空回答 + 短推理）。要测"长程任务里会不会绕圈"，
  得把 prompt-lab 接上真实的工具执行循环。
- `reasoning_summary` 显式设 `concise` / `detailed`：简单题上无差异（0/12），
  复杂题还没跑。
- 中文注入指令（`GOAL_INITIALIZATION_INSTRUCTION`、goal 状态注入、工具报错）与
  英文 system prompt 混用的影响。
- 每组 60+ 次的功效验证（现在多数结论的置信区间还很宽）。

## 踩过的坑

- **变体里的 `taskOverride` 会盖掉 `--task`**：`pe` 系列一度硬编码跑 study 题，
  于是"brief 任务"那一轮实际跑的是 Python 并发题，差点得出"PE 让回答变长 13 倍"
  的错误结论。现在 `--task` 是唯一入口，变体不再自带题目。
- 统计函数第一版把 Fisher 的最后一个阶乘项写错了（`b-d+x` 应为 `d-a+x`），
  所有 p 值都算成 1.0。重算比重跑便宜 —— 这也是把分析拆成
  `prompt-lab-analyze.ts` 的原因。

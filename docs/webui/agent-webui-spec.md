# Agent 桌面客户端 UI 规格说明（Spec）

> 给实现方（LLM）：请严格按本文档实现。凡本文未写明的细节，按"现代、克制、流畅"的原则自行决定，并在代码注释里说明取舍。不要擅自增加本文没有的功能。

## 0. 项目概述

- 类型：**桌面应用**（Electron 打包，同时代码必须能在浏览器里直接 `vite dev` 运行，方便调试）
- 技术栈：React（最新稳定版）+ Vite（最新稳定版）+ TypeScript
- 定位：一个 AI Agent 的聊天/执行界面，核心是「消息流 + 工具调用展示 + Todo 进度」
- 后端：本 spec 只涉及前端。后端通过 **WebSocket 或 SSE** 推送流式事件，前端**必须把数据层抽象成接口**（见第 9 节），首版用 mock 数据跑通全部 UI

## 1. 视觉设计规范

### 1.1 基调
- **白色背景**为主，整体风格：干净、留白多、轻阴影、低对比边框
- **统一圆角**：全站只用 3 档圆角，定义为 CSS 变量，禁止随手写数值
  - `--radius-sm: 8px`（小按钮、标签、代码行内）
  - `--radius-md: 12px`（卡片、工具块、输入框内部元素）
  - `--radius-lg: 20px`（输入框整体、大面板、消息气泡）
- 所有颜色、间距、圆角、阴影、动画时长/曲线，全部用 **CSS 变量（Design Tokens）**集中定义在一个文件里
- 颜色：
  - 背景 `#FFFFFF`，次级背景 `#F7F7F8`，边框 `#E8E8EB`
  - 文字主色 `#1A1A1C`，次要 `#6B6B76`，弱化 `#A0A0AB`
  - 强调色一个即可（默认蓝色 `#3B82F6`），成功/警告/错误各一个
- 字体：系统字体栈（`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`），代码用 `"JetBrains Mono", "Cascadia Code", monospace`
- 阴影：最多 2 档（`--shadow-sm` 卡片、`--shadow-md` 浮层），要非常淡
- 图标库：`lucide-react`（统一线条风格）
- 首版**只做浅色主题**，但颜色必须全部走变量，方便以后加深色

### 1.2 布局（从上到下）

```
┌─────────────────────────────────────────┐
│  标签页栏（Tab Bar）                     │  固定在顶部
├─────────────────────────────────────────┤
│                                         │
│  消息区（Message List）                  │  可滚动，占满剩余高度
│                                         │
├─────────────────────────────────────────┤
│  Todo 面板（有 todo 时才显示）            │
│  输入框（Composer）                      │  固定在底部
└─────────────────────────────────────────┘
```

- **没有左侧 session 列表**。每个 session = 一个顶部标签页
- 消息区内容居中，最大宽度 `760px`，左右自适应留白
- 窗口最小尺寸 `480 x 600`，小窗口下布局不能崩

## 2. 顶部标签页（Tab Bar）

- 每个标签 = 一个会话，显示：状态点 + 标题 + 关闭按钮（hover 才显示）
- 状态点：空闲（灰）、运行中（蓝色呼吸动画）、等待用户（橙色）、出错（红色）、有未读（蓝色小点）
- 「+」按钮新建标签，固定在最右侧
- 标签过多时：横向滚动，鼠标滚轮可横向滚动，左右边缘有渐隐遮罩
- 支持：拖拽排序、双击标题重命名、中键/点 × 关闭、`Ctrl/Cmd+T` 新建、`Ctrl/Cmd+W` 关闭、`Ctrl/Cmd+数字` 切换
- 选中态：用一条**滑动的圆角背景块**指示（切换时平滑移动，不是瞬间跳变）
- 标题默认取会话第一条用户消息的前 20 字，可被后端更新
- 新建/关闭标签有宽度伸缩动画
- Electron 下：标签栏兼作窗口拖拽区域（`-webkit-app-region: drag`），标签本身和按钮设为 `no-drag`；预留系统窗口控制按钮的位置（Windows 右侧、macOS 左侧红绿灯）
- **每个标签的状态互相独立**：消息、输入框草稿、滚动位置、Todo，切换回来必须原样恢复

## 3. 消息区

### 3.1 消息类型
1. **用户消息**：靠右，圆角气泡（`--radius-lg`），淡灰或淡蓝背景
2. **助手消息**：靠左，**不用气泡**，直接铺在白底上（更适合长文本和代码），可包含多个「块」：文本块、思考块、工具调用块
3. **系统提示 / 错误**：居中的小条，圆角，淡色背景

### 3.2 流式 Markdown 渲染（重点）
- 支持：标题、列表、任务列表、表格、引用、行内代码、代码块、链接、图片、分割线、GFM 全套；数学公式首版可不做，预留扩展点
- 代码块：语法高亮（用 Shiki，按需懒加载语言）、右上角「复制」按钮（点击后图标变 ✓ 并有小动画）、显示语言名
- **性能要求（最关键）**：
  - 流式过程中**只重新渲染最后一个正在增长的块**，已经完成的块必须用 `React.memo` 固定，不允许每个 token 都重渲染整篇
  - 做法：把 Markdown 按块（段落/代码块/列表…）切分，稳定的块用块内容的 hash 作 key，只有末尾块更新
  - 未闭合的 Markdown 语法（如没写完的 `**`、未闭合的代码围栏、半个表格）要能**优雅渲染**，不闪烁、不跳动
  - 流式文本更新做**批处理**：收到 token 后先入缓冲区，用 `requestAnimationFrame` 每帧最多刷新一次 UI，而不是每个 token 一次 `setState`
  - 用 `useDeferredValue` 或 `startTransition` 降低非关键更新的优先级
  - Markdown 解析建议在**独立块粒度**做，重解析放到空闲时间；必要时用 Web Worker
- 打字机效果：新增文字有极轻微的淡入（opacity 0.4 → 1，约 120ms），不要逐字位移
- 光标：流式进行时末尾显示一个闪烁的小圆点/竖线，结束后消失

### 3.3 滚动行为
- 新内容到来时：如果用户**在底部附近**（阈值 ~80px）则自动跟随滚动；如果用户已经向上滚动，**不打扰**，并在右下角显示「↓ 回到底部」浮动圆角按钮（带新消息计数）
- 跟随滚动要平滑，不能每个 token 触发一次强制滚动引起抖动（用 `requestAnimationFrame` 合并）
- 长对话必须**虚拟列表**（推荐 `@tanstack/react-virtual`），支持动态高度，首版就要做，否则 120 帧无法保证
- 滚动位置在切换标签后要恢复

### 3.4 消息操作
- 助手消息 hover 时，底部淡入操作栏：复制、重新生成
- 用户消息 hover：复制、编辑（编辑后从该处重新生成，首版可只做 UI 占位）
- 停止生成：流式期间输入框的发送按钮变为「停止」按钮

## 4. 工具调用展示（首版重点：折叠 + 信息简化）

原则：**默认只让用户看到"发生了什么"，不看"怎么发生的"**。

### 4.1 单个工具调用块
- 默认状态：**折叠成一行**（圆角 `--radius-md`，淡灰背景，高度 ~36px）
  - 内容：状态图标 + 工具名（人话化，如"读取文件""执行命令""搜索网页"）+ **一句话摘要**（如文件名、命令前 40 字、搜索词）+ 耗时 + 右侧展开箭头
  - 状态图标：运行中（旋转 loading）、成功（灰色 ✓，别用刺眼的绿）、失败（红色 ✕）、等待确认（橙色）
- 展开后显示：**输入参数**（格式化 JSON / 命令文本）和**输出结果**（默认最多显示 ~12 行，超出显示「展开全部」）
- 展开/折叠有高度过渡动画（用 `grid-template-rows: 0fr → 1fr` 技巧，避免 `height: auto` 动画卡顿）
- **失败的工具调用默认展开**错误摘要；成功的默认折叠
- 输出很大时（超过 1 万字符）必须截断显示，并提供「复制完整内容」

### 4.2 连续工具调用合并
- 助手一次回复中如果**连续出现多个工具调用**，合并成一个「分组」：
  - 折叠态：一行显示「执行了 5 个操作 ✓」，右侧箭头
  - 分组运行中：显示「正在执行：<当前工具摘要>」并有轻微流光动画
  - 展开分组后，里面才是逐个工具行（每个仍可单独展开）
- 分组默认折叠，运行中的分组默认显示最后一个正在运行的工具

### 4.3 思考块（Thinking / Reasoning）
- 如果后端推送了思考内容：显示为一行「思考中… / 已思考 8 秒」，默认折叠，点击展开看内容（弱化的灰色小字）
- 思考中带文字流光/呼吸动画，结束后静止

### 4.4 需要用户确认的工具（权限请求）
- 工具需要批准时，在该工具行下方内联出现一个圆角卡片：显示要做什么 + 「允许 / 拒绝 / 总是允许」按钮，标签页状态点变橙色
- 首版可做成 UI + mock，接口预留

## 5. Todo 面板（在输入框正上方）

- 位置：**紧贴输入框上方**，与输入框视觉上连成一体（同宽，同样的圆角体系，像输入框的"上半部分托盘"）
- **没有 todo 时完全不渲染**（不占位）；出现时从输入框上方向上滑出 + 淡入
- 每个 todo 一行：状态图标 + 文本；状态：待办（空心圆）、进行中（蓝色，带转圈或呼吸动画）、已完成（实心 ✓，文字置灰加删除线）
- **默认折叠，只显示 3 条**，右侧一个箭头按钮，点击展开全部 / 再点折叠：
  - 折叠时显示哪 3 条：**优先显示"进行中"的那条 + 它前后相邻项**；全部完成时显示最后 3 条。高亮当前进行中的
  - 折叠状态下，如果总数 > 3，箭头旁边显示「+N」或「3/8 已完成」这样的进度文字
  - 展开/折叠有平滑的高度动画；展开后如果条目很多（> 8），面板内部滚动，最大高度约 240px
- Todo 项状态变化（如待办→完成）要有过渡动画（图标 ✓ 弹出、文字渐变置灰），当前项变化时列表自动滚动到当前项
- 面板标题行：「任务 · 3/8」+ 折叠箭头，整行可点击
- Todo 属于**当前标签页**，各标签独立

## 6. 输入框（Composer）

- 圆角 `--radius-lg`，轻阴影，聚焦时边框变强调色（带过渡）
- 多行自适应高度（最少 1 行，最多 ~8 行，超出内部滚动）
- `Enter` 发送，`Shift+Enter` 换行；**输入法组合输入（IME，中文拼音）期间按 Enter 不能触发发送**（必须检查 `isComposing`，这是中文用户最常见的 bug）
- 发送按钮：圆形，无内容时置灰；流式期间变「停止」
- 支持粘贴/拖拽图片和文件，显示为输入框上方的小圆角缩略卡片，可删除（首版可先做 UI）
- 支持 `/` 命令和 `@` 引用的弹出菜单：**首版仅预留组件和接口，不必做全**
- 草稿按标签页保存，切换标签不丢

## 7. 动画与 120 帧性能规范（硬性要求）

### 7.1 动画原则
- 所有动画**只用 `transform` 和 `opacity`**（这两个属性走 GPU 合成，不触发布局/重绘）。禁止对 `width / height / top / left / margin` 做动画
- 需要"高度变化"的场景用 `grid-template-rows: 0fr ↔ 1fr` 技巧或 FLIP 技术
- 统一动画曲线与时长写成变量：
  - `--ease-out: cubic-bezier(0.22, 1, 0.36, 1)`
  - `--ease-spring`：弹性（用于弹出、按压反馈）
  - 时长：微交互 120–160ms，展开折叠 220–280ms，页面级 320ms
- 推荐使用 `motion`（原 framer-motion）的 `LazyMotion` + `domAnimation` 做布局动画和 `AnimatePresence`；简单的 hover/展开用纯 CSS transition。**不要每个小元素都上 JS 动画**
- 必须尊重 `prefers-reduced-motion`：开启时关闭位移动画，只保留淡入淡出
- 需要有动画的地方：标签切换/新建/关闭、消息出现、工具块展开折叠、Todo 展开折叠与状态变化、按钮按压（scale 0.97）、浮层出现、状态点呼吸、加载流光

### 7.2 性能硬指标
- 目标：在 120Hz 屏幕上，流式输出 + 滚动期间**不掉帧**（每帧预算 ≈ 8.3ms）
- 手段清单（都要做）：
  1. 消息列表虚拟化
  2. 已完成消息/块 `React.memo`，稳定 props，避免不必要重渲染
  3. 流式 token 用 `requestAnimationFrame` 批处理，每帧最多一次状态更新
  4. 流式状态放在**独立的 store**（推荐 `zustand` + selector 精细订阅），不要放在顶层 React state / Context 里，避免整棵树重渲染
  5. 长列表项使用 `content-visibility: auto` + `contain: layout paint style`
  6. 语法高亮、Markdown 大块解析放到空闲时间或 Worker；流式进行中的代码块**先用无高亮纯文本渲染，块结束后再高亮**
  7. 不使用大面积 `backdrop-filter: blur` 和大范围 `box-shadow` 动画（很吃 GPU）
  8. 图片懒加载并预留尺寸，避免布局抖动
- 开发环境内置一个**可开关的 FPS/渲染耗时小面板**（右下角，`Ctrl+Shift+P` 开关），方便验证
- Electron 注意：`BrowserWindow` 开启硬件加速（默认即是），不要设置 `backgroundThrottling: false` 以外无必要的选项；渲染进程里禁止在主线程做重计算

## 8. 我补充的、你没提到但首版建议一起做的设计

按优先级排序（前 6 项建议首版就做）：

1. **空状态**：新标签页的欢迎界面（简短标题 + 3～4 个建议提示卡片，点击填入输入框）
2. **停止 / 中断 / 重试**：流式中可停止；请求失败时消息底部出现「重试」按钮，错误信息友好化，原始错误可展开查看
3. **连接状态与断线重连**：顶部或输入框上方的细提示条（"连接中断，正在重连…"），自动指数退避重连，重连后从断点恢复
4. **标签页运行状态 + 桌面通知**：后台标签完成任务时标签出现未读点，窗口不在前台时发系统通知
5. **快捷键体系**：见第 2、6 节，另加 `Ctrl/Cmd+K` 命令面板（首版可占位）、`Esc` 停止生成
6. **会话持久化**：所有标签与消息保存到本地（Electron 用 IndexedDB 或文件；浏览器用 IndexedDB），重启后恢复标签页；首版接口抽象好即可
7. **无障碍**：键盘可完整操作；焦点环清晰（圆角一致）；标签页使用正确的 `role="tablist"`；动态内容用 `aria-live="polite"`
8. **设置面板**（后续版本）：模型选择、主题、字号、快捷键
9. **国际化**：文案全部走 i18n 字典（首版中文，预留英文），不要把文字硬编码在组件里
10. **错误边界**：每个标签页一个 ErrorBoundary，一个标签崩溃不影响其他标签

## 9. 数据层接口（先抽象，首版用 mock）

前端只依赖下面的事件协议，后端以后对接只需要实现这个适配器：

```ts
// 后端 -> 前端 的流式事件
type AgentEvent =
  | { type: 'message_start'; messageId: string }
  | { type: 'text_delta'; messageId: string; text: string }
  | { type: 'thinking_delta'; messageId: string; text: string }
  | { type: 'tool_call_start'; messageId: string; toolId: string; name: string; input: unknown }
  | { type: 'tool_call_end'; toolId: string; status: 'success' | 'error'; output: string; durationMs: number }
  | { type: 'tool_permission_request'; toolId: string; description: string }
  | { type: 'todo_update'; todos: { id: string; text: string; status: 'pending' | 'in_progress' | 'done' }[] }
  | { type: 'message_end'; messageId: string }
  | { type: 'error'; message: string };

// 前端 -> 后端
interface AgentTransport {
  send(sessionId: string, text: string, attachments?: File[]): void;
  stop(sessionId: string): void;
  approveTool(toolId: string, decision: 'allow' | 'deny' | 'always'): void;
  onEvent(handler: (sessionId: string, e: AgentEvent) => void): () => void;
}
```

- 必须提供 `MockTransport`：能模拟文字流式输出（含代码块、表格、未闭合语法）、多个连续工具调用、todo 变化、出错、权限请求。**没有后端也能完整演示所有 UI**
- 后端如果是 Rust/别的进程，Electron 中通过 IPC 或本地 WebSocket 连接，适配器里实现即可

## 10. 推荐技术选型（可以微调，但需说明理由）

| 用途 | 选择 |
|---|---|
| 框架/构建 | React + Vite + TypeScript |
| 状态管理 | zustand（细粒度订阅） |
| 动画 | motion（LazyMotion）+ 纯 CSS transition |
| Markdown | react-markdown 或 markdown-it + 自定义块级切分；GFM 插件 |
| 代码高亮 | Shiki（懒加载） |
| 虚拟列表 | @tanstack/react-virtual |
| 图标 | lucide-react |
| 样式 | CSS Variables + CSS Modules（或 Tailwind，二选一，全项目统一） |
| 桌面壳 | Electron（用 electron-vite 或 vite-plugin-electron） |

## 11. 目录结构建议

```
src/
  app/            # 入口、全局布局
  tokens/         # 设计变量（颜色、圆角、阴影、动画）
  components/
    tabs/         # 标签页栏
    messages/     # 消息列表、气泡、操作栏
    markdown/     # 流式 Markdown 渲染
    tools/        # 工具块、分组、思考块、权限卡
    todo/         # Todo 面板
    composer/     # 输入框
  store/          # zustand stores（每个会话独立）
  transport/      # AgentTransport 接口、MockTransport、真实适配器
  hooks/
  lib/
electron/         # 主进程、preload
```

## 12. 交付与验收标准

**分阶段交付**（每阶段都要能跑起来）：
1. 项目骨架 + 设计变量 + 整体布局 + 标签栏
2. MockTransport + 消息列表（虚拟化）+ 流式 Markdown
3. 工具块折叠/分组 + 思考块
4. Todo 面板 + 输入框
5. 动画打磨 + 性能验证 + Electron 打包

**验收清单**：

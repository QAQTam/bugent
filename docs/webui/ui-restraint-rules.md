# UI 克制守则（去 AI 味）

> 给实现方（LLM）：本守则与《Agent 桌面客户端 UI 规格说明》配套使用。**两者冲突时，以本守则为准。**
> 核心原则只有一条：**界面上的每一个元素，都必须能回答"用户为什么需要它"。回答不出来，就删掉。**

---

## 一、总原则

1. **默认不加**。没有被明确要求、也不是功能必需的元素，一律不加。宁可少，不可多。
2. **不做"看起来像 AI 产品"的装饰**。目标是像一个安静、精确的工具，不是一个在表演"智能"的产品。
3. **所有显示的内容必须有真实来源**。要么来自用户输入，要么来自后端数据，要么是功能必需的固定文案。**不允许编造、不允许占位当真**。
4. **同一信息只出现一次**。用户已经在别处看到的信息，不重复展示。
5. 拿不准要不要加时：**不加**，并在交付说明里列出"我没加但你可能想要的东西"，让用户决定。

---

## 二、禁止清单（硬性，出现即视为不合格）

### 2.1 无意义文字与"品牌感"文案
- 禁止任何自我介绍/自我标榜类文字，例如：
  - "Agent · 基于 XXX"、"Powered by XXX"、"由 XXX 驱动"、"AI Assistant"、"智能助手"
  - 技术栈、框架、模型名称、版本号出现在**非设置/关于页**的任何位置
- 禁止欢迎语、鼓励语、拟人化客套话，例如：
  - "有什么我可以帮你的吗？"、"很高兴为你服务"、"让我们开始吧！"、"准备就绪"
  - "思考中…请稍候"、"马上为你处理"、"稍等片刻～"
- 禁止营销式空状态标语（如"释放你的创造力"、"让 AI 为你工作"）
- 禁止装饰性 emoji（界面文案、按钮、标题、空状态里一律不用 emoji；用户消息内容里的除外）
- 禁止感叹号，除非是真正的错误警告
- 禁止无意义的副标题、说明性小字（如输入框下方常见的"AI 可能会出错，请核实重要信息"这类免责声明，**首版不加**）

### 2.2 重复与编造的数据
- 禁止展示任何**假数据、示例数据、占位数据**作为真实界面内容（如"今日已完成 12 个任务""节省 3.2 小时""响应时间 0.8s"）
- 禁止统计卡片、数据看板、成就徽章、使用量提示，除非本 spec 明确要求
- 禁止同一状态多处重复表达。例如：一个任务在运行，**只允许用一个地方表达"运行中"**（见 3.1），不能同时在标签页、消息里、输入框旁、标题栏都写一遍
- 禁止在工具块里同时显示"工具名 + 工具名的英文原名 + 图标文字说明"这种三重表达，一个就够
- 时间戳：每条消息不加时间戳；只在跨天或间隔很久时显示一条分隔，且 hover 才显示精确时间

### 2.3 默认动画惯式（AI 生成界面最典型的味道）
- **禁止**闪烁的圆点/竖线光标（流式输出末尾不要加任何光标；新文字用极轻淡入即可）
- **禁止**"三个跳动的小点"（typing indicator）
- **禁止**到处都是的呼吸/脉冲（pulse）动画。状态点默认**静止**，只有"运行中"这一种状态可以有动画，且同一屏幕内**最多同时存在 1 处**持续动画
- **禁止**流光/扫光/shimmer 文字效果（包括"思考中"文字流光）
- **禁止**弹跳（bounce）、过冲明显的弹簧动画、摇晃（shake）、旋转装饰
- **禁止**打字机逐字位移、逐字放大
- **禁止**骨架屏（skeleton）滥用：只有真实存在加载等待且超过 300ms 才允许，且不闪
- **禁止**页面进入时所有元素依次错峰飞入（stagger 入场）
- **禁止**背景动效：渐变流动、粒子、光斑、网格、噪点动画
- **禁止**鼠标跟随发光、卡片 3D 倾斜

### 2.4 视觉惯式
- **禁止**紫色/蓝紫渐变、任何渐变描边、渐变文字、渐变按钮
- **禁止**发光（glow）效果、彩色大阴影、毛玻璃（backdrop-filter）
- **禁止**"卡片套卡片套卡片"。同一区域最多两层容器
- **禁止**给每个元素都加边框 + 阴影 + 圆角三件套；一个元素最多用其中两项
- **禁止**装饰性图标：图标只用于"承担功能"（按钮、状态），不用于点缀标题或列表项
- **禁止**彩色图标底座（图标放在彩色圆角方块里）
- **禁止**大面积强调色。强调色只用于：焦点、选中、主要操作按钮、进行中状态。占屏面积应 < 5%
- **禁止**超过 3 种字号、超过 2 种字重出现在同一个界面里（整套界面建议：正文 14px、次要 12–13px、标题 16px，字重 400/500）
- **禁止**大标题、居中的大图标空状态

### 2.5 交互与结构惯式
- **禁止**顶部/侧边的品牌 Logo 区、产品名、版本号
- **禁止**"快捷提示卡片"墙（例如空状态里放 4 个"帮我写代码 / 帮我写文案…"的示例卡片）——**空状态只保留输入框**，最多一行淡色的简短提示（如"输入消息开始"）
- **禁止**任何"引导/教程/新功能提示"弹窗
- **禁止**在消息里加"以下是…""好的，我来…"这类由前端拼接的引导语（那是模型的内容，不是界面的内容）
- **禁止**为了"显得完整"而加入的设置项、开关、菜单入口

## 三、允许的动画（白名单）

只有下面这些动画是允许的。**不在白名单里的，不做。**

| 场景 | 效果 | 时长 |
|---|---|---|
| 展开/折叠（工具块、Todo、分组） | 高度平滑过渡 + 内容淡入 | 200–260ms |
| 标签切换 | 选中背景块平移 | 200ms |
| 标签新建/关闭 | 宽度伸缩 | 200ms |
| 新消息出现 | 淡入，位移不超过 6px | 160ms |
| 流式新文字 | 极轻淡入（opacity 0.5→1） | ≤120ms |
| 按钮按下 | scale 0.97 | 100ms |
| 浮层/菜单出现 | 淡入 + 位移 ≤ 6px | 140ms |
| Todo 完成 | 图标切换 + 文字置灰 | 200ms |
| 运行中指示（全屏唯一） | 一个小型旋转图标，或细线条匀速移动，二选一 | 持续 |

- 所有动画使用统一曲线变量，不允许每处自己写贝塞尔
- 动画的目的只有一个：**让状态变化可被感知**。装饰性的动画一律不要
- `prefers-reduced-motion` 下只保留淡入淡出

## 四、文案规则（界面上的字）

1. **只写事实，不写语气**。
   - 对：`已读取 config.json`　错：`太棒了，我已成功为您读取了配置文件！`
2. **短**。按钮 2–4 个字，状态 ≤ 8 个字，提示 ≤ 20 个字。
3. **用动词 + 对象**描述工具动作：`读取 config.json`、`运行 npm test`、`搜索 "react vite"`。不要出现"正在为您…"。
4. **错误信息**：说清楚"发生了什么 + 用户能做什么"，不道歉、不卖萌。
   - 对：`连接已断开。正在重试（第 2 次）`　错：`哎呀，出错了～请稍后再试！`
5. **不出现第一人称**（"我""我们"），界面不是在说话，模型才是。
6. **数字与单位**：耗时 `1.2s`、`3m 12s`；数量直接写数字；不加修饰词。
7. **文案必须集中管理**（i18n 字典），并且**每条文案都能在代码里追溯到它的触发条件**。没有触发条件的文案不允许存在。

---

## 五、信息简化规则

1. **默认只显示结论，细节需点击**。
   - 工具调用：一行摘要，展开才有参数和输出
   - 错误：一句话，展开才有堆栈
   - 思考：默认折叠
2. **摘要里不重复标题里已有的信息**。
3. **状态用图标/颜色表达，不用文字重复**。已经有 ✓ 图标就不再写"已完成"。
4. **数量多时归并**，不逐条罗列（见 spec 中的工具分组）。
5. **长内容截断并给出明确的"展开"**，绝不让某一条内容撑满整个屏幕。
6. **一个屏幕内，用户视线应该只有一个焦点**（通常是最新消息/当前进行中的动作）。

---

## 六、实现自检（每个阶段交付前必须自己过一遍）

实现方在交付每个阶段时，**必须附上下面清单的逐项结果**，并列出"我判断为必要但 spec 没写的元素"（附理由），由用户决定是否保留：

- [ ] 界面上是否出现任何产品名、技术栈名、版本号、"AI/Agent/智能"字样？（应为否）
- [ ] 是否出现任何欢迎语、鼓励语、客套话、免责声明？（应为否）
- [ ] 是否存在任何硬编码的示例数据/统计数字被当作真实内容展示？（应为否）
- [ ] 是否有同一状态在两处以上重复表达？（应为否）
- [ ] 是否出现闪烁光标、跳动圆点、呼吸脉冲、流光文字、错峰入场？（应为否）
- [ ] 同屏持续动画是否 ≤ 1 处？
- [ ] 是否使用了渐变、发光、毛玻璃、彩色大阴影、彩色图标底座？（应为否）
- [ ] 是否有装饰性 emoji 或装饰性图标？（应为否）
- [ ] 每个元素是否都能说出"用户为什么需要它"？
- [ ] 所有文案是否都是事实陈述、无语气词、无第一人称？
- [ ] 所有动画是否都在白名单内？

## 七、当规则没覆盖到时

按这个顺序决策：
1. 有没有比"加一个元素"更简单的办法？（比如什么都不加）
2. 能不能复用界面里已有的样式/组件？
3. 如果必须新增：选最朴素的、最不引人注意的样式；不加动画；不加图标；文案最短。
4. 在交付说明里标出这个决定，让用户确认。
